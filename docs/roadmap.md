# Project roadmap

This is a proposed roadmap, not a release promise. Maintainers should approve priorities and create issues before assigning work.

| Area | Current state | Proposed next step |
|---|---|---|
| Core Q&A | Registration, questions, tags, comments and search present | Regression testing and usability improvements |
| Analytics | Event collection and staff summary present | Verify end-to-end behavior and counting rules |
| Documentation | Setup, schema, API and policy guides | Review links and test setup on supported systems |
| Privacy | Policy and documented controls | Registration notice, account deletion and proposed six-month analytics retention |
| Community safety | Code of Conduct | Confirm private reporting channel and moderation workflow |
| Security | Policy and deployment guidance | Dependency review and production configuration checks |
| Portability | Configurable API and local setup | Self-host fonts where practical and test independent deployment |
| Releases | Public deployment not re-verified | Verify hosting, document tested versions and publish release notes |

Suggested order: verify core functionality, address privacy and reporting gaps, improve portability, then prepare a documented release. No dates or owners are assigned without team approval. See [DPG assessment](dpg_self_assessment.md).
